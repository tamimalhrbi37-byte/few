# نظام التحكم عن بعد بالكمبيوتر (Remote Desktop System)

هيكلة كاملة (Skeleton) لمشروعك مكوّنة من 3 أجزاء، جاهزة للتطوير والتجربة.

```
📱 Flutter App  ──WebSocket (إشارات)──►  🌐 ASP.NET Core Server  ──WebSocket (إشارات)──►  💻 Agent (الكمبيوتر)
     │                                          (Relay فقط، لا يفهم المحتوى)                      │
     └──────────────────────── WebRTC (فيديو الشاشة + Data Channel للأوامر) ─────────────────────┘
```

بعد تبادل رسائل الإشارات (offer/answer/ice) عبر السيرفر، يتصل الجوال والكمبيوتر مباشرة مع بعض
عبر WebRTC لبث الشاشة وإرسال أوامر التحكم - السيرفر لا يشوف الفيديو ولا الأوامر إطلاقاً.

## هيكل الملفات

```
remote-desktop-system/
├── server/RemoteDesktop.Server/     ← سيرفر الـ Relay (ASP.NET Core + WebSocket)
├── agent/RemoteDesktop.Agent/       ← برنامج الـ Agent على الكمبيوتر (.NET 9, Windows فقط)
└── app/                             ← تطبيق الجوال (Flutter)
```

## 1. تشغيل السيرفر (Server)

```bash
cd server/RemoteDesktop.Server
dotnet run
```

يشتغل افتراضياً على المنفذ 5080. عند النشر على استضافة حقيقية (مثل Azure, Railway, أو VPS)،
حط الـ Server خلف HTTPS/WSS (عبر Nginx أو Reverse Proxy) عشان الاتصال يكون مشفّر.

## 2. تشغيل الـ Agent (على الكمبيوتر)

```bash
cd agent/RemoteDesktop.Agent
dotnet run
```

أول تشغيل بينشئ ملف `config.json` فيه:
- `ServerUrl`: غيّره لعنوان السيرفر الفعلي (مثال: `ws://myserver.com:5080/ws`)
- `PairCode`: كود عشوائي يظهر في الطرفية - انسخه واستخدمه في تطبيق الجوال

**باقات NuGet المطلوبة** (تُنزّل تلقائياً عند `dotnet restore` بشرط اتصال إنترنت):
`SIPSorcery`, `SIPSorceryMedia.Encoders`, `SIPSorceryMedia.Windows`

## 3. تشغيل تطبيق الجوال (Flutter)

```bash
cd app
flutter pub get
flutter run
```

في الشاشة الأولى، أدخل عنوان السيرفر ونفس كود الاقتران، ثم اضغط "اتصال".

## المزايا المُنفّذة في الهيكلة

- ✅ تحريك الماوس (نسبي - touchpad style، أو مطلق لموضع معيّن)
- ✅ نقر يسار/يمين (نقرة = يسار، ضغط مطوّل = يمين)
- ✅ كتابة نص عبر لوحة مفاتيح الجوال
- ✅ اختصارات: Alt+Tab, Win, Escape, Enter, Backspace (قابلة للتوسيع بسهولة)
- ✅ إطفاء/إعادة تشغيل الجهاز (مع مهلة 5 ثوانٍ وإمكانية الإلغاء)
- ✅ بث الشاشة عبر WebRTC (VP8)
- ✅ واجهة عربية بالكامل (RTL)

## ⚠️ نقاط مهمة تحتاج انتباه قبل الاستخدام الفعلي

1. **Ctrl+Alt+Delete**: ويندوز يمنع برمجياً محاكاة هذا الاختصار تحديداً لأسباب أمنية
   (Secure Attention Sequence) - ما ينفع عبر `SendInput` العادي. الحل: تجاهله (نادراً تحتاجه)
   أو استخدام مكتبة/تعديل صلاحيات متقدمة (خارج نطاق الهيكلة البسيطة).

2. **TURN Server**: حاطين STUN عام من قوقل بس. إذا صار عندك مشاكل اتصال (خصوصاً لو الجوال
   على بيانات الجوال مو نفس شبكة الواي فاي)، بتحتاج TURN server (مثل coturn - مجاني ومفتوح
   المصدر، تقدر تشغله على نفس السيرفر).

3. **الأمان**: كود الاقتران (`PairCode`) حالياً هو الحماية الوحيدة - تأكد إنه طويل وعشوائي
   وما تشاركه لأحد. للاستخدام الشخصي البحت هذا كافٍ، لكن لو نويت تنشره لأكثر من جهاز/شخص
   لاحقاً، بتحتاج طبقة مصادقة حقيقية (Authentication).

4. **الأداء**: التقاط الشاشة حالياً عبر `System.Drawing` (بسيط لكن أبطأ نسبياً). لو احتجت
   أداء أعلى (60fps، دقة عالية)، ننتقل لاحقاً لـ Desktop Duplication API (DXGI) مباشرة.

5. **الكود مو مُختبر بالكامل**: هذا سكيلتون كامل ومترابط منطقياً، لكن ما قدرت أشغّل/أبني
   المشروع فعلياً في بيئتي (ما عندي وصول لـ NuGet/pub.dev من هنا)، فممكن تحتاج تعديلات
   بسيطة في أسماء methods/إصدارات المكتبات (خصوصاً SIPSorceryMedia.Encoders) حسب آخر
   إصدار تنزّله. جرّب `dotnet build` و`flutter analyze` أول شي وابعث لي أي خطأ يطلع.
